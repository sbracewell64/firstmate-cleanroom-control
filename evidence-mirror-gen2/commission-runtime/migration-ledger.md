# Clean-room runtime migration ledger, 2026-09-02

From `/mnt/e/FirstMate-Cleanroom/runtime/firstmate` (drvfs / 9p, no file modes)
to `/home/OPERATOR/.firstmate-cleanroom` (ext4, WSL native).

Only the **private mutable runtime** moved. The pinned upstream checkout, the
clean-room tools, the evidence tree, the experiments and the exchange directory
stay on E: exactly where they were.

Nothing was deleted. The source home is retained in place as evidence and
carries a `MIGRATED.md` pointer.

## Why

The upstream authenticated listener registrar (`bin/fm-check-register.sh`)
requires a private check script at **exactly mode 0700**, one link, not a
symlink, on the same device as the state directory
(`fm_pr_private_file_valid`, `bin/fm-pr-lib.sh:266`). The drvfs mount carries no
file modes, so `chmod 0700` there resolves back to `777` and the registration
refused with `error: custom check is unavailable`. That is a property of the
mount, not of the script: the identical registrar accepts the identical bytes on
ext4. Measured both ways in `chmod-semantics.txt` and
`listener-registration.txt`.

## Left behind, with reasons

Every one of these is volatile state keyed to the OLD home's session, process or
path. Copying any of them would have imported a claim that is false in the new
home. This is the difference between migrating a runtime and copying a directory.

| Item | Why it was left |
|---|---|
| `state/.watcher-down` | A downtime token (`pending:downtime:1139658.1788312666.1gL5S2`) describing a watcher in that home. The new home has its own watcher state; importing this would assert a downtime that never happened here. |
| `state/.session-start-complete` | Holds `784718`, a process id from the 2026-09-01 session in the old home. Meaningless and actively misleading in a new home. |
| `state/.wake-queue`, `state/.wake-queue.seq` | Held one queued wake from 2026-09-01 announcing that deferred startup network checks had finished. `state/.startup-network.status` in the same home records `state=done rc=0`, so replaying it would wake a session for work already completed. The new home starts with an empty queue and generated its own. |
| `state/.startup-network.{report,status,timings}` | Results of a probe run in the old home, keyed to that session's `generation=` and `lock_pid=`. A new home must probe for itself, and it did. |
| `state/.trace-context-effective` | `784718 off` - the same dead process id. Trace context is off by default. |
| `state/.inactive-outcome-reconcile` | A reconciliation cursor bound to the old home's epoch. |
| `state/home-summary.json` | A generated snapshot that literally records `"home": "/mnt/e/FirstMate-Cleanroom/runtime/firstmate"`. Carrying it would have made the new home assert a summary of a different home. Regenerated by the new home's own session start. |
| `projects/` (empty) | Nothing to carry; recreated empty. |

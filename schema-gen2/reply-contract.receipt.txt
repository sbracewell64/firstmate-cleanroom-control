Required fields (12):
  - schema: exactly "fm-sol-control/v2"
  - kind: exactly "receipt"
  - receipt_id: string matching ^fscp2-[0-9a-f]{32}$
  - in_reply_to: string matching ^fscr2-[0-9a-f]{32}$
  - correlation_id: string matching ^fsc2-[0-9a-f]{32}$
  - vocabulary_digest: string matching ^[0-9a-f]{64}$
  - control_config_generation_digest: string matching ^[0-9a-f]{64}$
  - consumed_at: string matching ^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$
  - consumer: object with 3 required fields
      - login: string
      - kind: one of: "human" | "agent" | "automation"
      - provenance_class: one of: "self_asserted_descriptor" | "forge_recorded_binding"
      - optional: forge_binding, session_ref
  - validation: array of object
      - predicate: string
      - value: one of: "observed-good" | "observed-bad" | "could-not-observe"
      - optional: evidence_ref, measured, narrowed_from, narrowing_binding, narrowing_evidence_class, narrowing_reason, read
  - verdict_class: one of: "PASS" | "FAIL" | "CNO"
  - outcome: one of: "CONSUMED" | "REFUSED_MALFORMED" | "REFUSED_MISMATCH" | "REFUSED_STALE" | "REFUSED_STALE_CONFIG" | "REFUSED_AMBIGUOUS" | "CNO_TRANSPORT" | "CNO_INCOMPLETE_UNIVERSE" | "CNO_TOOL_UNREACHABLE" | "NO_ANSWER" | "WITHDRAWN" | "CNO_TRUNCATED_RESPONSE"

Conditional companion fields:
  - when outcome == "CONSUMED":  consumes_ruling_id, ruling_comment_id, ruling_sha256, consumption_identity, applied, replay_check is REQUIRED
  - when outcome != "CONSUMED":  applied, consumption_identity, replay_check MUST BE ABSENT (present is refused)

Optional fields (8): applied, consumes_ruling_id, consumption_identity, note, replay_check, resulting, ruling_comment_id, ruling_sha256

Rules the consumer enforces mechanically (a violation is refused, never repaired):
  - additionalProperties is false on every object: an unknown or misspelled field
    name is REFUSED_MALFORMED and the refusal names the field.
  - schema: Compared by EXACT STRING EQUALITY, never by substring or prefix. 'fm-sol-control/v2'
      contains 'fm-sol-control', so a consumer matching on word overlap would consume
      retired-venue v1 traffic. See venue_isolation.match_rule in the canonical control config.
  - receipt_id: Derived; inputs and order owned by $defs.id_derivation. The receipt identity is
      therefore a function of exactly what was consumed, so a second consumption of the same
      ruling cannot produce a different receipt identity.
  - in_reply_to: EXPLICIT AND STABLE. Derived, never assigned; the inputs and their order are
      owned by $defs.id_derivation in this file and are read from there rather than transcribed.
      Recompiling the same request at the same generations yields the same id, so 'have I
      already asked this?' is a lookup and not a judgement; any generation moving yields a
      DIFFERENT id, so a stale ruling cannot even address the new subject.
  - correlation_id: Derived; inputs and order owned by $defs.id_derivation. Venue unit is one
      issue per correlation_id, which bounds the comment universe so the completeness predicate
      is cheap and always satisfiable.
  - validation: THE WHOLE LADDER, pass or fail, every predicate evaluated and none skipped.
      Every failing predicate is reported, not only the first.
  - verdict_class: Folded under the precedence FAIL > CNO > PASS. There is no
      continue-with-a-warning value. An empty result set, an unreadable record, an absent
      artifact, an unreachable tool and a silent verifier are all CNO and none of them is PASS.
  - outcome: CONSUMPTION OUTCOME, closed and total over every reachable terminal. EVERY terminal
      state produces a receipt, refusals and withdrawals included: a refusal that leaves no
      receipt is a silently abandoned request. REFUSED_STALE_CONFIG is the captain addendum's
      terminal for a ruling bound to a prior control-config generation: the ruling stays
      historical evidence and zero action is taken. NO_ANSWER (nothing arrived before
      expires_at) is recorded APART from INSUFFICIENT_EVIDENCE, which is an answer.
      CNO_TRUNCATED_RESPONSE (generation 2) is the terminal for an authority-bearing forge
      response that arrived truncated: the ruling universe was not seen whole, which is a
      different fact from an unreachable tool and from an incomplete pagination universe, and it
      has a different repair -- re-read through a non-truncating surface.
